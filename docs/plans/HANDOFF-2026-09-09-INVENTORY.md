## The five things worth knowing before you touch it

1. **This shop has no shelf numbers** (owner, 2026-09-09, §1.4). `aisle`/`row`/`bin` are optional and
   nothing requires them. **Do not lead a Parts form with them.** What addresses a shelf here is the
   label — `tag_code` and D-INV7's resolver, which arrive at I6/I10.
2. **A movement id is generated by the CLIENT** and is the idempotency key (D-INV27). The web form
   must mint one UUID **per movement**, not per attempt — a retry sends the same id and gets the same
   row back with a 201. Minting per attempt breaks the offline queue's server half and breaks no test.
3. **`/low-stock` is deliberately unpaginated.** It returns the whole list because a low-stock screen
   that under-reports says "nothing to order" and is believed. Do not add `limit`/`offset` to it.
4. **Errors carry a code and a status that mean something.** 409 = the shelf refuses a fine payload
   (`IV010` not enough, `IV011` ledger not editable, `IV016` retry). 422 = the payload names something
   unusable (`IV012`/`IV013`/`IV014`/`IV015`). The screens should render the message, not "failed".
5. **`lint:filesize` covers `.vue`** — measured at I0, 500 hard / 450 warn. Extract the forms from the
   first commit rather than after the gate fails.

## A3 is ruled — I4 has no blocker

The plan's default is adopted: **a locked-header CSV template with an error report.** The reason it is
safe is D-INV10 and not convenience — **the shelf is ours**, so FleetPal never becomes an ongoing
source of parts even after it lands, and the initial import is therefore ONE-TIME whatever file
arrives. A FleetPal export gets re-headed once in a spreadsheet. **Do not build a column-mapping UI**;
it is a screen for a job nobody does twice.

## Traps this programme has already paid for

- **A comment claiming a hazard that measurement denies is worse than no comment.** `/by-upc/:upc`
  carried one about route ordering; moving the route failed no test, because two path segments cannot
  collide with one. Mutate before you warn.
- **`supabaseRecorder` does not filter** — `.eq()` is recorded, not applied. Use function fixtures or
  `pages`, or a flat array will answer two different questions with the same rows.
- **zod STRIPS unknown keys** rather than rejecting them. To prove a field cannot reach the database,
  assert on what was written, not on a 400.
- **A fresh worktree needs `pnpm install` + `build:rn` + two `.env` files**, or ~14 suites fail for
  reasons that are not your change.
- **Run all 38 `lint:*` scripts before pushing**, not the 28 CI names — `lint:schema-snapshot` and
  three others are chained onto neighbours.
