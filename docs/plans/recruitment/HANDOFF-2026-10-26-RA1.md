## 3. Hiring Profile v1 (the seed data, ruled 2026-10-26)

| Requirement | v1 rule | Evidence level that satisfies it |
|---|---|---|
| Age | ≥ 23 | DOB `self_reported` (Part 1) → `document` (CDL) |
| Experience | ≥ 2 years **verifiable** Class A | `self_reported` → `verified` only by an employer reply (`employer_inquiries.outcome='responded'`) or MVR issue date; else `unknown` |
| Licence | Class A CDL | `document` |
| Hazmat | preferred — sorts higher, never required | `document` |
| Disqualifiers (hard) | CMV DUI ever / any DUI ≤ 5 y · preventable DOT-recordable accident ≤ 3 y · Clearinghouse prohibited · positive/refusal without RTD | MVR, PSP, Clearinghouse, D&A inquiry — `document`/`verified`; applicant's own answer is `self_reported` |
| Violations short of that | **no numeric limit** — show 3-year counts, verdict `unknown`, recruiter judges | MVR |
| Hiring area | not ruled (Q-LS2) — information only, **never ZIP** (HB 3773) | — |

A `does_not_meet` sorts below and is labelled; **nothing auto-rejects** (D-LS3, D-RA3).

## 4. Traps, measured

- `sms_consents.driver_id` is NOT NULL (`mig/0233:34`); a lead cannot hold consent until RA1.2.
- `callClaude` returns the fuel tool's JSON; do not call it for anything else until RA1.8.
- `hire.ts` reads `roster: manage` from the org's matrix (`sections` claim), not the role table —
  the SP5 comment explains why; widen there, not in `shared/auth.ts` alone.
- No CAPTCHA and in-memory per-replica limiters (`middleware/applicationLimits.ts:55-58`); RA1's
  intake routes are **authenticated** (paste box, API) so this is RA5's problem, not RA1's.
- `notify()` categories need the contract **and** the DB CHECK (`mig/0521:308-317`) — if RA1 adds
  an alert, both change in the same migration/PR pair.
- The applicant IS the driver row (D-HIRE5). `convert_lead` creates that row; it must carry the
  lead's `channel/source/campaign` onto it (a nullable `drivers.lead_id` or a `lead_conversions`
  table — prefer the table; `vehicles.status`-style column sprawl is the thing to avoid).
- `lint:comment-claims`: a comment that says "proves" must quote a real test title.
- Every PR body follows the four headings of `.github/pull_request_template.md`; `gh pr create
  --body-file` skips the template, so write them in. Title = release-note line for an office reader.
- Run the gates and **check `$?`** before pushing (`pnpm lint` is not the gate set — see root
  `package.json` `"//lint:*"` keys and `.github/workflows/ci.yml` `gates`).
- Tests prove themselves: list the mutation that went red in the PR's "Tests" section.
- Branch from `origin/main` (`claude/<topic>`); parallel chats share one working tree.
