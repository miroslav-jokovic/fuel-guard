## 4. Rules and patterns this codebase enforces — learned the hard way this session

### The house rules that bit

- **`getSupabaseAdmin` is the SERVICE ROLE and bypasses RLS.** Every query carries its own
  `.eq("org_id", …)` — *including updates by an id you just created*. `expectOrgScoped` caught
  `settle()` doing exactly that.
- **`env.test.ts` refuses a fallback for a key that already has a schema default.** `pspHost` had
  `env.PSP_ENVIRONMENT ?? "uat"` and the schema already defaulted it — two sources of truth for the
  value that decides whether a request bills.
- **New table → `enable row level security`**, and evidence tables go in `RETENTION_FORBIDDEN`
  (`dataRetention.ts`) or a retention rule can quietly prune them.
- **Migrations are next-numbered and additive.** `create or replace function` in a NEW file is the
  established way to change an old one (0089/0096/0154 do it).
- **A comment claiming test coverage must quote a real test title** (`lint:comment-claims`).
- **500-line file budget.** `routes/recruitment.ts` hit exactly 500 and was split into
  `routes/recruitment/{employment,authorizations}.ts` on the `routes/roster/` pattern.

### Test-harness facts that cost time

- **`createSupabaseRecorder` returns its fixture WHATEVER filters ran.** That is what makes
  `expectOrgScoped` possible — and it means "the response was empty" proves nothing about filtering.
  **Assert on `q.filters()`, not on the result.**
- The recorder's `.select().single()` after an insert returns the **fixture's first row**, so a table
  with an empty fixture makes an insert path look like a 500.
- **It now has a `storage` surface** (added this session). `storageCalls()` records bucket + method.
- **`env.test.ts` and `auditEntityId.test.ts` enumerate with `git ls-files`** — an unstaged deletion
  leaves them reading a path that no longer exists. **Stage file moves before running the suite.**
- **The EFS registry's constraint scanner used to take the LAST `check (status in …)` in the whole
  migration directory.** It was right only by accident; `0216` made it wrong. It is table-scoped now.
- PGlite matrices: with RLS and no UPDATE/DELETE policy a statement **matches zero rows and
  SUCCEEDS**. Assert the row is unchanged, not that it threw.
- `$2` used for two different column types in one PGlite insert makes Postgres refuse to deduce the
  parameter. Pass it twice.
- `pnpm build` needs `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`; CI sets dummies at job level.

### The mistake I made three times — worth naming

**`field: over.field ?? default` in a test fixture helper silently restores the default when a test
passes an explicit `null`** — hiding the exact rule the test was written for. It happened in the PSP
validator fixture and again in the cross-match fixture. **Spread the overrides instead.**

### Regulatory patterns that shaped the design

- **§391.21(b)(10) is 3 years of ALL employment; (b)(11) is the 7 before that, CMV ONLY.** A
  ten-year timeline is not ten years of everything, and **gap detection stops at the three-year
  boundary** — `SegmentB` has no `gaps` field at all, deliberately.
- **FCRA §604(b)(2): the disclosure must be in "a document that consists SOLELY of the disclosure".**
  Courts read *solely* literally. One row IS one document; there is nowhere to store an omnibus consent.
- **PSP bills on Success, Partial AND Failure; `Error` is free.** Every pre-flight rule is money, and
  each cites the §8.5 detail code it prevents.
- **PSP corroborates or discovers; it can NEVER refute.** A driver can work two years and never be
  inspected.
- **Advisory ≠ required.** PSP and ELDT are `advisory: true` in `dqCatalogue` — reporting them
  `missing` would paint lawful files red.
- Empty arrays are **answers**, not omissions — hence `declares_no_accidents`.

### Voice

Comments explain WHY at length, cite decision IDs and CFR sections, and name the incident or defect
that caused them. Commit messages are one descriptive sentence in the `git log` narrative style, and
the body says what was learned. Branches `claude/<topic>`, PRs to `main`.

## 5. Why a UAT token, in one paragraph

Not mainly cost. The guide's Introduction restricts PSP data to the driver or an account holder with
that driver's **written consent obtained before the request**. Testing software is not an employment
purpose, so without UAT the **first real hire becomes the rehearsal** — and if the parser is wrong we
have spent money *and* possibly filed a wrong record about someone whose job depends on it. UAT gives
three known test drivers (`SUSAN GODFREY`/PA, `GARY THOMAS`/GA+PA — the only way to exercise `Partial`,
`JOSE DAVIS`/VA, `dotNumber` 43586) for free with nobody's privacy involved. Get one at
`uat.psp.tylerapp.com` via Login.gov → Web Service → Request an API Token; access to the test
environment may need PSP support (`PSPhelp@tylertech.com`, 1-877-642-9499).

**If UAT proves unobtainable**, the fallback is deliberate rather than accidental: `PSP_MONTHLY_LIMIT=1`,
flip `PSP_ORDERS_ENABLED`, order for one real applicant who has signed, and read the ledger row before
anything else. `response_raw` is stored whole, so a wrong projection is re-derivable without re-buying.
