## 1. Q-HM9 — the investigation is a step (#880)

`employment_investigation`, ordinal **13b**, evidence `employer_inquiries`, blocking `hired`. No
migration; 0223 has existed since August.

**Two rulings the plan's one-line recommendation did not settle.** Both are argued at the step's own
row in `hiringSteps.ts`; the short version:

- **`federalGate: false`, and §5's pinned six stay six.** The flag does not mean "required by law" —
  it means one of the six a carrier must hold BEFORE THE DRIVER FIRST DRIVES. §391.23(c)(1) gives the
  carrier **30 days from the date employment begins**, so this is lawfully open on day one.
- **`beforeTravel: false`, hence 13b and not 5b.** §391.23(a)(1) (the MVR) and (a)(2) (this) are the
  same regulation's two halves and 5b is where it first went. It was moved because a step inside 1–9
  gates `readyToTravel`: previous employers take weeks on a clock that is **theirs**, so gating the
  plane ticket would stall every hire for a third party's silence, or push an office into documenting
  a non-response early to clear the row — a **weaker** file. ⚠ **If the owner wants travel gated on
  it, that is one field and a test.**

⚠ **The trap, if you touch this fold.** `driverInquiryQueue.complete` is `outstanding.length === 0`,
which is **vacuously true before anybody types an employment history**. The fold requires the
application to be FILED before zero is allowed to mean zero — and requires the opposite too, because
a first-time driver with no DOT-regulated employer in the window genuinely has nobody to write to.
Absent input is **not done**, fail-closed.

⚠ **A count cannot answer a question about state.** `inFlight` was `attempts > 0` and rendered
*"Waiting on them"* over an employer nobody had written to. `inquiryQueue.ts` has four open states
and only **`awaiting`** is the employer's move. The fold takes `awaiting`, never a tally.

## 3. Why the next step is B7

Everything on the applicant's side of the wizard is repair-free and unblocked, B7 is half a day, and
it is `∥` — **so it wants its own chat, today, not a place in a queue**. §10's own lesson from Wave A
is that a `∥` step nobody schedules is never late and therefore never done.

**B7 is two additions and neither touches the machinery:**

1. **An expectations screen** — say how many steps and roughly how long, before they start.
2. **Per-step time estimates on `ApplyProgress`'s list.**

### ⚠ Three rulings already in `ApplyProgress.vue` (Q-AX1). Do not redo or undo them

1. **The bar INDICATES; the list NAVIGATES.** Nine segments on a 320px phone is ~30px each — a third
   of a comfortable touch target — so *"a driver aiming for step 3 in a moving truck hits step 4"*.
   The bar is `aria-hidden` because the heading and counter already say it in words.
2. **Forward is fenced at the HIGH-WATER MARK, not the current position.** `next()` validates the
   screen being left; jumping does not. Reaching an unvisited screen from the list would be a way
   around validation.
3. Everything navigable is a real button with a real label.

⚠ **B7's row says it explicitly: do not touch the bar or the fence.** The additions hang off the
list, not the navigation.

### The recommendation worth having before you start

**Put the minutes ON the catalogue, not in a map beside it.** The eight screens live in
`packages/shared/src/applicationSections.ts` (`APPLICATION_FILLING_SECTIONS` +
`APPLICATION_SECTION_LABELS`). A `Record<ApplicationSection, number>` in `apps/web` would be a copy
with a delay fuse — add a section, forget the entry, and the newest screen silently has no estimate.
This is exactly what `HIRING_STEPS` did for `action` and `phase` (B4) and what
`HiringEvidenceTable`'s closed union did for artifacts (B5): **make the estimate a property of the
section, so a section cannot exist without one.**

⚠ And the estimate is a fact about the FORM, which the applicant's screen and the office's
expectations copy must both read — so it belongs in `packages/shared` for D-HM2's reason, not in the
component.

## 4. The traps, all measured, all still live

| | |
|---|---|
| **Rendering finds what tests cannot — TEN steps running** | B4 three · B5 one · B6 two · A3 one · A4 three · Q-HM9 one. ⚠ **Open the page.** B7 is a 390px job and its row says so |
| **⚠ A test can keep passing while the document under it is replaced** | A2's *"signs nothing"* sliced a block out of a document that no longer had one: both `indexOf` calls returned -1, the slice returned `""`, and `""` contains nothing. **It proved the absence of a string in an empty string.** When you change what a surface renders, re-read its tests — green is not evidence they still point at anything |
| **A mutation coming back GREEN usually means the TEST is at fault** | three of eight in A2, one of six in Q-HM9. In every case the fixture was too uniform to discriminate — all-or-nothing states, one `kind` of row, no partial case. **Write the partial case** |
| **`pnpm --filter @silvicom/web build` fails for this** | it needs the two `VITE_` vars as REAL env vars, not the `.env` file. `preview:local` handles it, and takes whatever port is free (it took **:4178** today — four other sessions held 4173–4177) |
| **A mutation harness must not revert with a checkout** | write the original BYTES back and assert the digest. A `git checkout --` is refused in a worktree-isolated session and does nothing, silently |
| **`rm` is refused by the sandbox classifier** | move files to the scratchpad instead; it is reversible and is not blocked |

## 6. The protocol, unchanged

One step, one PR, one branch off `origin/main`. ⚠ Several chats share this working tree — check
`git branch --show-current` before every commit. Record progress by **appending a dated line to §10**;
never tick a row in §9. Run the gates before pushing. **Prove a test can fail** by mutating the line
it covers — and if a mutation comes back green, **suspect the test before the code**, because four
times out of four this week it was the test.

⚠ And the one every wave keeps proving: **the suite being green is not the verification.** Ten
consecutive steps have shipped a defect every test passed for, each found only by opening the page or
rasterising the document. Budget for it.
