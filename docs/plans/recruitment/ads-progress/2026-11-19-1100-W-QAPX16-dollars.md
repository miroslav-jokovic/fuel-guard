**2026-11-19 · Track W · Q-APX16: the picture and video budget in US dollars, each price asked of Higgsfield**

- **Why.** Higgsfield's API has no credits. Its billing page prices in dollars, and `POST /estimate/<model>` answers
  `{"usd":"0.094"}`, "the authoritative amount" for the account (billing-and-retention.md, re-read 2026-11-19: a
  string, one field, no error codes named, no word on whether it charges).
- **0634 (#2558)** widens `ad_generations.cost_unit` to `usd`, one merge ahead of the writer. `credits` stays allowed
  because the ledger is append-only and the simulator wrote some on staging.
- **Settings.** `higgsfield_usd_cents_monthly` (null refuses, like tokens). `higgsfield_credits_monthly` is RETIRED,
  read by nothing, still defaulted to null for one release so a version saved now parses on the old code; it can go
  once this reaches production. The form shows "Pictures and video, dollars a month".
- **The money is exact.** The estimate's string is read digit by digit into hundredths of a cent (`usdTicks`), the
  precision of `cost_units` numeric(14, 4). Anything finer is rounded UP, so the month can only overstate. The row
  records both `price_usd` (Higgsfield's words) and `price_ticks`; the completion writes `"0.4000"` as a string.
- **The order in a render.** switch → a month already past its budget (price 0) → upload the photo (free) →
  estimate with the final params → `renderGate(used + price ≤ budget)` → row. A refused estimate is a failed row
  at no cost (`estimate_<status>`, `estimate_unreadable`, `estimate_balance`), never no row, which would leave
  compose queueing a job that never writes one. A temporary one is pending with no row.
- **Before and after the deploy.** A row begun by the old code still in flight completes in the credits it was priced
  in. The dollar month does not count credits rows, and the health read sums one unit only (dollars when present).
- **Spend read.** `ai.credits_used`/`credits_budget` became `pictures_used_cents`/`pictures_budget_cents` (the web is
  served by the same deploy); the card rounds a fraction of a cent up.
- **Sweep.** The estimate joined the L3 crash sweep as a kill point and as two fault paths. Its fault patterns had to
  be anchored: `/qwen-image-3|wan-3\.0/` also matched `/estimate/alibaba/...`, so a "submit" fault fired on the price
  ask. A temporary estimate failure with a photo uploads the photo twice (no row yet); uploads are free.
- Mutations, each alone, each red: an estimate refusal ignored, no pre-check before the upload, a render charged
  nothing, an unreadable estimate taken as free, old credits counted in the dollar month, renders in flight not
  counted, the gate off by one, no rounding up, mixed units summed in the health read, the card rounding down.

- The Automation tab shows a `usd` agent in dollars to the cent, rounded up (`agentUnits`).
