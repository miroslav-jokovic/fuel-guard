**2026-11-14 · Track W · V1a — the AI rail takes any current model**

Built, with no model moved: `AI_MODEL_PROFILES` (shared `ai.ts`) says per model whether it accepts a forced tool
and how many tokens of thinking headroom it needs; `AD_AGENT_MODELS` (shared `ads/agentModels.ts`) names the
model and effort of each of the six Claude agents, every line still `claude-sonnet-4-6`. `callForcedTool`
(`lib/anthropic.ts`) reads the profile through one function, `wireShape`: a forced-tool model is asked exactly as
before; Opus 5.5, Sonnet 5.5 and Fable 5.2 are asked with `tool_choice: auto`, at most one call, and one fixed
sentence naming the tool. A model with no profile throws before any call or ledger row. `stop_reason: "refusal"`
is its own outcome (`refused`, with the provider's category) and fails the ledger row under that code.
The ledger stores what was sent; on a forced-tool model the stored request and its hash are unchanged
(pinned by "on a forced-tool model the stored request and its hash are what they were before V1").

Two corrections to ADS-PLATFORM-V2-PLAN §4 V1, made in the plan by this PR:

- **Not structured outputs.** The plan said `output_config.format`. Strict outputs refuse `minLength`, `maxLength`,
  `minimum` and `maximum` (claude-api skill, JSON Schema Limitations), and the workers' schemas use them; a tool
  under `auto` keeps every keyword, and the answer is validated by the same Zod schema as before.
- **No server-side fallback.** The plan said it would be on. A ledger row names one model; an answer that a
  second model gave would be recorded as the first's. A refusal fails the row instead.

that worker's `baseline.json` was recorded on. `lint:agent-fixtures` never knew the model.
