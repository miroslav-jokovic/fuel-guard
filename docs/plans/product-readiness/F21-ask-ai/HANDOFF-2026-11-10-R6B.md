## How to build each tool (the established shape, R1 → R6b)

1. **Owner module first (D-AI2):** `modules/<owner>/assistant<Thing>.ts` calls the page's OWN function and only renames fields. The only logic it may own is calendar (`@silvicom/shared` `assistantPeriods.ts`: `resolveAssistantRange`, `assistantMonthsIn`, `assistantWeeksIn`, `assistantPreviousRange`, `assistantWholeMonths`, `assistantUnitKey`) and name lookup. Export it from the module's `index.ts`.
2. **Register it:**
   - add an `ASSISTANT_TOOL_ACCESS` entry with exactly the page route's gates (`view(section)`, plus `bought(module)` if the route has `requireModule`);
   - add a definition in `insights/askTools.ts` (`askTools.test.ts` fails on drift);
   - add a `runTool` line in `insights/askData.ts`, and a `vi.mock` of the module index in `askData.test.ts`;
   - add a boundary edge with a WHY comment in `scripts/check-feature-boundaries.mjs` (`insights -> <owner>`);
   - add a suggestion on the page's surface in `apps/web/src/components/assistant/suggestions.ts`.
3. **Every result carries** `source` (the page, by name and path), its freshness (as_of, through-day, last sync), and the reason when a figure is withheld. Never zeros for "no data".
4. **Tests:**
   - spy on the page function and assert it was called with the page's exact arguments, and that a fixture's figures are copied unchanged (choose fixture values a recomputation could not reproduce);
   - `expectOrgScoped`;
   - role reach (derived automatically in `assistantContract.test.ts`; add named facts).
5. **Deliberate breaks:** mutate, see a test fail by ASSERTION (not a ReferenceError or compile error; memory `a-no-op-mutant-is-not-a-survivor`), restore, and confirm green. If one survives, add the test that kills it.
6. **Plan:** append a §6 Log entry at the END of PLAN.md. Parallel merges conflict there; resolve by keeping both entries in merge order.

## Working rules that bit this session

- **Worktree from origin/main**, then setup:

  ```sh
  git worktree add ../FG-<topic> -b claude/<topic> origin/main
  pnpm install --frozen-lockfile
  pnpm --filter @silvicom/shared build:rn   # re-run after ANY shared change, before api/web tests
  cp ../FuelGuard/apps/web/.env apps/web/.env
  cp ../FuelGuard/apps/api/.env apps/api/.env
  ```
- Read-only production SQL: `supabase db query --linked "<sql>"` (real org `86d6b3ea-4361-4f71-877f-e8373615769b`). No writes.
- **Verify a plan's premise against the code before building on it.** Today the plan said "accounting = admin and accountant only" (the auditor has view too), and a page comment said "the query layer converts the bound" (it didn't since 09-04). Both were wrong.
- **Web and API deploy separately.** Any change to a request's meaning ships server first, tolerant of the old client, and the client a release later.
- A full local `pnpm --filter @silvicom/api test` can flake once (e.g. `inventory.test.ts`). Rerun the file alone before believing it.
- PR flow: open the PR with the template's four headings (`--body-file` skips the template), wait for CI, and merge yourself when CLEAN. If the PR shows DIRTY, merge `origin/main` in (usually the PLAN.md log) and push again.
