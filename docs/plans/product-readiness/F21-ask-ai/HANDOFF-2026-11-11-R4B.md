| Tool | Page | URL state today | PDF/CSV the page already has |

| `loads_by_truck` | `/loads` | `queue`, `delivered_from`, `delivered_to`, `truck` (vehicle id), `driver` | none |

| `idle_report` | `/idling` | sub-states `trucks`/`drivers`/`capability`; check the window keys | — |
| `finance_report`, `income_statement` | `/fleet-report` | **period NOT in the URL** (`ref<ReportPeriod>`, `FleetPeriodRail`) | statement PDF? check |
| `card_holds` | `/fuel-cards` | `status` and others (`fuelCardsFiltersInUrl.test.ts`) | CSV export |

**Recommended design (D-AI6, stated so it is not reinvented):**

1. **One shared link builder per page, read by the page and the tool.** Add `packages/shared/src/<page>LinkContract.ts`. Each one exports:
   - the page's URL keys as constants, and
   - `toQuery(filters)` / `fromQuery(query)`.

   The page's composable (e.g. `useSpendFilters`) reads its keys from it, and the owner module's
   assistant tool returns `link: { surfaceKey, query }` built by the same `toQuery`. A link built
   anywhere else is a second source of truth (CLAUDE.md "No workarounds").
2. **The link travels as structured data, never as model text (D-AI8).** Extend the response
   additively: `pages: string[]` stays, and a new `links: { surfaceKey, query }[]` is added. Then:
   - `askData` collects each successful tool's `link` from its result before `stripNeverExposed`;
   - the route returns them;
   - `useAnswerPages` renders `RouterLink :to="{ path, query }"` after the same reach check.

   An older web ignores `links`. The new web falls back to `pages`. One merge.
3. **Vehicle ids, not unit numbers.** `trucks=` takes ids. The fuel tool already resolves units to vehicles (`assistantFuelReport`). Return the ids in `link`, never in the model-facing text.
4. **PDF = the page's own export.** Once the link opens the page with the same filters, the page's PDF button prints exactly that figure. Do not build an assistant PDF renderer. The answer-level "Download CSV" from R4a stays for the model's table.
5. **Order:**
   - (a) Fuel costs: URL state and PDF exist; just the contract + `link`.
   - (b) IFTA: `q=`.
   - (c) Loads.
   - (d) Recruitment, Drivers, Fuel cards.
   - (e) **Fleet report last:** its period must move into the URL first. That is its own PR on that page: `?from=YYYY-MM&to=YYYY-MM` via `useQueryState`, round-tripped by `periodForCustom`. It is worth doing for the page anyway, since a link to a month cannot be shared today.
   - Tools that sum raw tables (`ASSISTANT_TOOL_PAGE` = null) get no link, as in R4a.

**Tests per slice:**
- the page reads its own contract (the page test passes with the contract's keys);
- the tool returns `link` from `toQuery` for a fixture whose filters a hand-built URL would get wrong (unit → id, quarter key, exclusive vs inclusive day);
- the web draws it only when reachable.

Deliberate breaks as before: mutate, see a test fail by assertion, restore.

## Open questions: findings and the approved solutions

### Q-AI12. Fuel costs page `manage("fuel")` vs its report route `view`

**Found:**
- `surfaceCatalogue.ts:111` gates `fuel.spend` (`/fuel-spend`) with `manage("fuel")`, and so is `fuel.spend.buy-discipline`.
- `GET /api/fuel-spend/report` and `/api/fueling/report.pdf` ask `requireSection("fuel", "view")`.

**History (researched):**
- FUEL-SECTION-CONSOLIDATION-PLAN T2 (PR #446, 2026-09-01) deliberately moved every fuel-spend READ route to the view set. Its own "Done when" says *"an accountant … can generate the spend report"*.
- The page's `manage` gate predates that. It comes from the old Fuel Spend tabs that held writes, and FS2 removed the tabs.
- So the route reflects the later, explicit decision, and the page is the stale half.
- Today an accountant can download the Fuel costs PDF through the API but cannot open the page. Ask AI's `fuel_report` follows the route.

**Approved: open the page to `section("fuel")` (view)**, with Buy discipline too if it holds no write (check first).
- One line in `surfaceCatalogue.ts` plus `namedGrantGates`/surface tests.
- It changes who sees a sidebar entry: accountant, auditor and dispatcher by default.
- With this approved, dispatchers get the page too, as the matrix already gives them the report. The alternative below is recorded only, not built. **If the owner had not wanted dispatchers on fuel spend** (D-SEP10 once noted *"a dispatcher reading fuel spend nobody decided they should read"*), the honest fix is the dispatcher's `fuel` access in the matrix, which narrows the routes, the page and the tool together. Never narrow only the page or only the tool.

### Q-AI4. Retention

**Found:**
- There are no conversation tables: the thread lives in the browser tab (Pinia), and a reload starts empty.
- What persists:
  - `ai_assistant_usage` (0584): tokens and cost, no text. It has no retention rule.
  - The `ai.ask` row in `audit_logs`: question, answer (≤4,000 chars), tools with inputs, outcome, cost, `history_turns`.
- `audit_logs` is in `RETENTION_FORBIDDEN` (`org/dataRetentionForbidden.ts`), so those rows are kept forever. Measured: 21 rows, 2.6 KB of meta in total.

**Approved:**
- (a) Add a retention rule for `ai_assistant_usage` at 13 months (`org/dataRetention.ts`; budget in `scripts/table-modules.json`). That covers the year-over-year cost view.
- (b) Keep the `ai.ask` audit row as is. It is a compliance record of who asked what with which access. Its answers derive from data the person was entitled to, with D-AI7 fields already stripped. The volume is trivial.
- (c) Keep conversations tab-local; R3b (persisted history) stays unbuilt until somebody asks for it. If it is built: 90 days, author-only, RLS deny-all, served only by the API.

## Working rules that bit last session

- **Worktree per PR from a PINNED sha:**

  ```sh
  base=$(git rev-parse origin/main)
  git worktree add ../FG-<topic> -b claude/<topic> $base
  pnpm install --frozen-lockfile
  pnpm --filter @silvicom/shared build:rn      # again after ANY shared change
  cp ../FuelGuard/apps/{web,api}/.env into the worktree
  ```

  To squash: `git merge <new pinned sha>`, then `git reset --soft <that same sha>`. NEVER `reset --soft origin/main`: a fetch in between made a squash revert another PR (#2213). Before pushing, check `git diff --stat <base> | tail -1` and `gh pr view N --json files` against what the PR should touch.
- **Conflicts** are always in PLAN.md, askData(.test).ts, askTools.ts, assistantContract(.test).ts and check-feature-boundaries.mjs: keep both sides, main's first. An auto-resolver once cut a tool definition in half; typecheck after every resolve, and read each `it(` boundary.
- **Gates:** run every `pnpm lint:*` that `ci.yml` runs, plus `pnpm lint` and `pnpm typecheck`. Re-run typecheck alone if its exit code is unclear.
- **Known flakes:** `efsCardControl.test.ts` (5 s timeout on CI), `metaWebhook.test.ts`, and the web `pageLoadFailureRetry.test.ts > DispatchLoadDetailPage`. Rerun alone before believing them; `gh run rerun <id> --failed` for CI.
- **Read-only production SQL:** `supabase db query --linked "<sql>"`. No writes.
- **PR flow:** template's four headings in the body (`--body-file` skips the template), wait for CI, merge yourself when CLEAN, merge `origin/main` in when DIRTY.
- **Web and API deploy separately.** A change to a request's meaning ships server first, tolerant of the old client, and the client after the server is in PRODUCTION.
