## Next step: R6a, finance tools

Goal: answer "cost per mile" (asked twice in production, 09/23 and 11/02, and it fails today), the
fleet report, and per-truck P&L. Reachable by **admin and accountant only**.

What is already there (verify at the call site; graphify is a map, not the territory):
- `apps/api/src/modules/financial/index.ts` exports `getFleetReport(admin, orgId, fromIso, toIso)`,
  which returns `FleetReportResult` with `monthsCovered`, `monthsMissing`, `monthsPartial`,
  `monthsOpen`, `openNote`, `closeKnown` and `sweptAt` (the freshness and close facts an answer must
  state). Its arithmetic is `computeFleetReport` in `@silvicom/shared`.
- Also exported: `getIncomeStatement`, `getFleetTrend`, `getTruckDays`, `getMileageCoverage`,
  `getLedgerCoverage`, `getMonthCloses`.
- The page routes are `apps/api/src/modules/accounting/routes/index.ts`: `/fleet-report`,
  `/income-statement`, `/fleet-trend`, `/truck-days`, `/mileage-coverage` and others, all behind
  `requireSection("accounting", "view")`. The surface is `finance.fleet-report` at `/fleet-report`, gate
  `section("accounting")`.

How to build it, the same shape as R1:
1. Owner module first (D-AI2): add `modules/financial/assistantFinanceReport.ts` (or under
   `accounting`, wherever the page's function lives). It calls `getFleetReport` / `getIncomeStatement`
   and **never recomputes a figure**. The only arithmetic it may own is calendar resolution (reuse
   R1's `resolveReportRange` pattern; consider lifting it to shared) and unit-number lookup.
2. Register each tool in `ASSISTANT_TOOL_ACCESS` with `[view("accounting")]`, and add its definition
   to `insights/askTools.ts`. `askTools.test.ts` fails if the two lists drift.
3. Every result carries its source and freshness: the page path, the months covered, missing,
   partial and open, `openNote`, and `sweptAt`. The answer must say when the McLeod GL close has not
   landed. Never present an open month as final.
4. Tests: the figures equal the page's for the same window; `expectOrgScoped`; an accountant has the
   tool and a fleet manager does not (`assistantContract.test.ts` derives this automatically). Add
   suggestions to the `finance.*` surfaces in `components/assistant/suggestions.ts`, each naming its
   tool. Run the deliberate-break checks (mutate, confirm a test fails, restore).
5. A boundary edge `insights -> financial` (or `-> accounting`) is needed in
   `scripts/check-feature-boundaries.mjs`, with a comment explaining it.

After R6a, in order: R6b idle trend (`safety`), live "moving now" (`dispatch`), loads and miles per
truck (`dispatch`), IFTA by state (`fuel`), maintenance cost per unit (`maintenance`), card holds
(`fuel`), DQ and inspection expirations (`roster`/`safety`), recruiting counts (`recruitment`;
D-AI7 applies). Then R3a (follow-up questions: send recent turns, no migration), R4 (CSV/PDF and

## Working rules that bit this session

- Work in a worktree from `origin/main` (`git worktree add ../FuelGuard-<topic> -b claude/<topic>
  origin/main`), then run `pnpm install --frozen-lockfile`, `pnpm --filter @silvicom/shared build:rn`,
  and copy `apps/web/.env` and `apps/api/.env`. The main checkout is shared with parallel chats.
- Moving a gate inside a handler trips `routeGates.test.ts` and `routeGateLedger.test.ts`. Pin the
  mount in `apps/api/src/testing/routeLedger.ts` with an argument that quotes the real test titles.
- `lint:boundaries` needs an explicit edge for every new cross-module import.
- `lint:filesize` is at 500 lines. `surfaceCatalogue.ts` is at 493, so shrink before adding.
- A full local `pnpm test` flakes on 5-second web timeouts and API socket errors. Rerun the failing
  files alone before believing a failure.
- PR flow: open the PR, wait for CI, and merge yourself when it's green. If GitHub had an outage and
  no checks appear, re-push.
