## 2. The one paragraph that matters most

**Ten assertions written today passed and proved nothing, and every one was caught by mutating the
subject rather than by reading the test.** That is not a run of bad luck, it is the dominant failure
mode of this codebase's test style, and it has a shape: **a fixture too uniform to discriminate.** Every
row on the 15th, so an inclusive-vs-exclusive bound could not move the count. Every row with gallons, so
a `clear` count with an extra condition matched the complement exactly. A mock answering every URL with
the same payload. A `DataTable` that renders as cards under jsdom, so "the headers do not include
Trailer" passed because there were **no headers at all**.

**So: a new test is unproven until you have watched it fail.** Mutate the subject, not the test. Two of
the ten were structural rather than fixture problems and could not be fixed at all — see §3.3.

## 3. Traps and findings — the part a fresh chat would waste a day rediscovering

### 3.1 The reusable finding: SQL returns a MEASUREMENT, TypeScript owns the VERDICT

D-AG1 (*"THIS SUMS. IT DOES NOT DERIVE"*) reads like a wall between SQL and any rule with a constant in
it. It is not. Every threshold comparison splits into a quantity SQL can compute **without knowing the
threshold**, and a comparison TypeScript makes:

| Judgement | What SQL returns | Who compares |
|---|---|---|
| `span > MIN_WINDOW_ADVANCE_MI` | the span | TypeScript |
| `obd.length >= 2` | the count | TypeScript |
| monotonic within ±1 | **the worst backward step**, `min(v - lag(v))` | TypeScript |
| the MPG plausibility band | Σ(mpg·gallons), Σ(gallons) | band passed **in** as a required argument |

The third row is the one that looks impossible and is not. The fourth is the other half: a parameter
with **no DEFAULT** cannot drift, so passing a constant *into* SQL is the opposite of copying it there.

### 3.2 Gates

- ⚠ **`lint:migration-ordering` does not see FUNCTIONS.** It reads added *columns*. A new RPC merged
  with its reader 404s for the ~9-minute deploy window exactly as a column would. **The gate's silence
  is a gap in the gate, not permission** — ship an RPC and its reader in two merges, and check
  `select proname from pg_proc` before merging the reader.
- ⚠ **`lint:table-writers` greps COMMENTS.** A comment containing `.from("vehicles").update()` failed
  the gate as a real write site.
- **`vehicles` is owned by `roster`** and `samsara` has exactly ONE grandfathered write site for it, on
  a list that may only shrink. Route new writes through `writeVehicleTelematics()` rather than pinning
  the same debt twice.
- **`lint:ui-adoption` rejects a hand-written `<table>`.** Use `DataTable`, even in a settings card.

### 3.3 Two tests that could not be made to work, and why that is the finding

- **A suppression guard is invisible to a SUM.** `robustWindowMiles` returns null rather than 0 for a
  non-advancing window — the guard its own header calls the most important one it makes. In
  `useFuelRangeTotals` that is **unfalsifiable**: `null ?? 0` and `0` both contribute nothing. The
  assertion was DELETED, with the reason left in its place, and the guard stays pinned in
  `windowMilesAggregate.test.ts` where it can actually fail. A test that passes whether the code exists
  or not is worse than no test.
- **`has_anomaly` is NOT NULL**, so 0289's `coalesce(has_anomaly, false)` can never fire. Kept as intent;
  the matrix says so rather than inserting a null the database rejects.

### 3.4 Postgres

- ⚠ **`LEAST` IGNORES NULLS.** `least(min(step), 0)` returns **0** where the spec returns null. Found
  only because the matrix asserts against the imported TypeScript rather than a hand-written expectation.
- **A matrix CAN import `packages/shared/dist`** — CI builds it at ci.yml step 48, before `pnpm test`.
  Use it: assert SQL against the real specification function, never against a restatement of it.
- **The feed's `hasNextPage` is ALWAYS true.** On a delta feed it means "this stream continues". A
  `while (hasNextPage)` walk never terminates; an empty `data` array is the end.

## 5. ⚠ FUEL-T5 is under-specified on one surface — decide before building

> **ANSWERED 2026-09-02 (Q-FUI14): Cards drops the attribution fact.** It carries rows-in-window and
> last-feed-poll only. The rest of this section stands as the reasoning behind that ruling.

T5 says *"Fuel Log, Transactions, Rejections and Cards each carry one line: rows in window, share
attributed to a vehicle, and last feed poll."* Three of those four are clear. **"Share attributed to a
vehicle" has no meaning on the Cards page** — a card is issued to a driver or a truck as a matter of
setup, not attributed to one per row, so there is no denominator. Options: give Cards a different third
fact (cards seen on the last sync vs cards held), or drop the third fact there and say so.

Also worth knowing before starting:
- **The Fuel Log has no attributed count to show.** `fuel_range_totals` (0289) returns `fills` but not
  "fills naming a truck". Adding it is a migration — and because `create or replace` cannot change a
  `returns table` shape, it is a `drop`+`create` in one transaction (safe: an extra column is ignored by
  the old reader).
- **Last feed poll** comes from `posted_last_polled_at` / `rejected_last_polled_at` on the EFS SOAP
  credentials row (already read by `efsSoapCredentials.ts`) and the `jobs` ledger — **not a new column**.
- The patterns to generalise are `IftaLedgerPage`'s `health` computed and
  `features/reconcile/PriceCoverageStrip.vue`. Both render **above** what they qualify.

## 8. Method, which is not negotiable

- **Measure before claiming, and re-measure the plan's own numbers before quoting them.**
- **Prove every test can fail by mutating its SUBJECT**, and say in the PR which mutations you ran. If a
  mutation does not fail the test, the test is the problem — fix the fixture or delete the assertion and
  say why. §2 is what happens when this is skipped.
- One step per PR, branched from `origin/main` **explicitly**, CI green, merge commit.
- **Hold a reader PR until its column OR FUNCTION exists in production** (`information_schema.columns`,
  `pg_proc`).
- When a step ships, mark it **DONE** in its plan with "What shipped" and "Verified by:" naming real
  test titles. When a question is answered, strike it through in place with the answer and the date.
- **When the honest fix is out of scope, record it as an open question with a recommendation.**
