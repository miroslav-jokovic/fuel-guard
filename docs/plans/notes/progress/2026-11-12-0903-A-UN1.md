## B2 — `lint:migrations` refuses the merge-list line §4.1 asks for

§4.1 and M11 say `DRIVER_REASSIGNMENTS` gains `{ table: "unit_notes", column: "subject_id", orgScoped: true }`.
`scripts/check-driver-references.mjs` (chained in `lint:migrations`, run in CI's `gates` job) refuses it:

```
✗ DRIVER_REASSIGNMENTS lists unit_notes.subject_id but no migration defines that drivers(id) FK — stale entry, remove it
```

The gate pairs every list entry with a `references drivers(id)` column, in both directions. `subject_id` is
polymorphic (D-UN1) and cannot carry that FK, so the gate has no way to tell this entry from a stale one.
The gate's four buckets (list, REFUSAL_SET, HANDLED_IN_FUNCTION, EXEMPT) all classify an FK the gate
*found*; none admits a driver reference that is not an FK. The file is in no track's §7.3 list.

What the matrix proves either way: with the line, a merge moves a driver's notes and touches no truck's or
trailer's notes; without it, the merge aborts on UN014 instead of losing notes. So nothing is lost while
this waits, but **a driver with notes cannot be merged** until the line is in.

Candidate answers:

- **(a) Teach the gate about polymorphic driver references — recommended.** A fifth set in
  `check-driver-references.mjs`, e.g. `POLYMORPHIC = new Map([["unit_notes.subject_id", "0592: subject_kind
  'driver' + subject_id; no FK possible; the guard moves only driver rows (UN012)"]])`, whose keys count
  as found, so the list entry is legal and a missing entry is still reported (the same "accounted for"
  rule, read from a declared table instead of an FK). About 6 lines plus a `--self-test` case that the
  set's entry is reported when the list drops it. Cost: one small PR to a file nobody owns; the
  orchestrator can give it to track A in this PR (§7.3 amendment) or make it its own.
- **(b) Move notes inside `merge_driver_v2`'s body** (as `documents` and `certifications` are, by
  `subject_type`/`subject_id`). Rejected: D-SEP5/0264 moved every mechanical move OUT of that body so it is
  never re-issued; re-issuing it for one table undoes that decision.
- **(c) Leave the line out.** Rejected: drivers with notes become unmergeable (UN014), a regression hidden
  behind a green gate — a workaround in CLAUDE.md's sense.

## What differed from the plan

1. **`table-writers.json` gets no line in UN1.** §4.1 lists it among the registries, but the gate pins
   *existing* `.from("…").insert/update/delete` sites and fails on a pinned path that writes nothing
   ("stale"). No application code writes `unit_notes` until UN2, so **track B adds
   `"unit_notes": ["apps/api/src/modules/roster/notes/<file>.ts"]` in UN2's PR**. That file is track A's
   in §7.3; this entry hands that one line to B. `check-table-producers` is satisfied now by the DML
   inside `set_unit_note_pinned` and the mention trigger.
2. **A second index for the wall**, `(org_id, created_at desc, id desc)`. §4.1 names only the per-unit
   index, but the Notes page (D-UN13) reads every note of the carrier newest first, which the per-unit
   index cannot serve without a sort.
3. **`author_id` may go to null.** §4.1 declares `author_id → auth.users (set null)`; a guard refusing
   every other edit would refuse that set-null and so stop the deletion of any login that ever wrote a
   note. The guard allows exactly `author_id: <id> → null`; `author_name` keeps the signature. (0535's
   `applicant_notes` has this defect — `AN011` refuses it — so a person who ever wrote an applicant note
   cannot be deleted from `auth.users` today. Not touched here: recruiting's table, not track A's file.
   Recorded for the orchestrator.)
4. **The insert guard answers before the CHECK.** A kind outside the three is refused `UN012` (the guard
   finds no such unit), not `23514`; the CHECK still stands behind it and the matrix reads it.
5. **TRUNCATE is refused too** (`UN010`, a statement trigger). Not in §4.1; row triggers do not fire on
   TRUNCATE, so "never deleted" needed it.

## Decisions taken inside §4.1's shape (each pinned by the matrix)

- **Who may be named (UN015):** a membership in this carrier, role not `driver`, `suspended_at` null.
  **Track B: UN3's `/people` must list exactly this set**, or the composer offers a name the insert refuses.
- **Merge and pins:** a duplicate's pinned note arriving on a driver who has one arrives unpinned (the
  surviving driver's pin wins); without that the merge died on `ux_unit_notes_one_pinned` (23505).
- **Merge and trucks:** the merge's update matches `subject_id` alone. A truck or trailer note sharing the
  duplicate driver's uuid stops the merge with UN012 instead of being re-pointed at a driver.
- **Typo pass threshold 0.4**, set on the function: measured, `word_similarity('brakse', 'Brakes adjusted
  at Petro')` is 0.57, under the extension's 0.6 default.
- **`after` cursor** returns the OLDEST `limit` notes newer than the cursor, newest first, so a refresh after
  more than 50 new notes asks again and skips none. `p_to` is exclusive, `p_from` inclusive (the half-open
  interval `dayRangeInstants` gives).
- **`unit_note_summary`** returns every asked kind as a key, `{}` when it has no notes.
- **`pg_trgm` is in `public` on production** (read-only query, 2026-11-12), so `operator(public.<%)` and
  `public.gin_trgm_ops` are right there and in PGlite.
