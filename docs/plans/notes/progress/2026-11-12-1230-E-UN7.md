## Not built — B3: the bell's route, `lib/notificationRoute.ts`

**The plan and the code disagree.** §6 UN7 says the bell route for `unit_note_mention` opens the
drawer on that note. UN3 rings with `entity_type: "unit_note"` and `entity_id` = the note id
(B-UN3 entry, "differs from the plan"). The drawer's address needs the unit's kind and id as well
(`?notes=<kind>:<subjectId>&note=<noteId>`). `notificationRoute()` is synchronous and sees only the
row, so it cannot produce that address. Something has to call UN3's `GET /api/notes/:id` first, and
on every branch (UN5, UN6, UN8) nothing does: a bare `?note=` opens nothing. Every place that could
make the call is a file track E does not own (§7.3).

default.
