## B3 — ruled (a) by the orchestrator 2026-11-12, built here

**The disagreement (kept for the record).** §6 UN7 says the bell route for `unit_note_mention` opens
the drawer on that note. UN3 rings with `entity_type: "unit_note"` and `entity_id` = the note id
(B-UN3 entry), while the drawer's address also needs the unit (`?notes=<kind>:<subjectId>&note=<noteId>`),
and `notificationRoute()` is synchronous and sees only the notification row. Candidates were (a) the
bell goes to `/notes?note=<id>` and the web resolves the unit with `GET /api/notes/:id`; (b) UN3 rings
with the unit as entity (loses the note, goes stale on a driver merge); (c) an async resolver inside
`NotificationBell.vue` (a second navigation path in a shared component). **Ruled (a)**, and for this
step track E owns `components/notes/useNotesDrawer.ts` and `pages/NotesPage.vue` as well (track C is
finished).

**Built:**

- `lib/notificationRoute.ts`: `unit_note_mention` + `unit_note` + an id → `/notes?note=<id>`. While the
  surface is dark (D-UN14) `opens('/notes')` is false for non-admins, so their entry informs without
  navigating.
- `useNotesDrawer.ts` gains `useNoteOnlyLink(enabled)`: when the URL has `note` and no `notes`, it asks
  `GET /api/notes/:id` once and REPLACES the URL with `formatNotesParam` of the note's unit and the
  note, so the drawer opens on that unit, marking the note, and Back leaves the page rather than
  landing on an address that would resolve again. It records the unit's label the way `open()` does,
  so the drawer's title names the unit at once.
  - **404** (another carrier's note, or no such note; UN3's route says neither which): `note` leaves the
    URL quietly, the reader is on the wall, no toast.
  - **Any other failure:** the same, plus a toast "Could not open the note", because a retry can help.
  - An id that is not a record id is dropped without asking. The answer is used only if the URL still
    asks for that note, so a reader who moved on is not dragged back. `enabled` is the viewer's
    `notes` surface (`useNotesAccess`): somebody without it asks nothing.
  - It reads the answer as `UnitNoteCreateResponse` (`{ note }`): the frozen contract has no separate
    read type and UN3's route answers the same shape. Not a contract change; noted for O in case a
    `UnitNoteResponse` name is wanted later.
- `NotesPage.vue` calls it: the bell's destination is the page that already mounts the one drawer.
  A note-only link pasted on another page is not resolved there; no caller produces one.
