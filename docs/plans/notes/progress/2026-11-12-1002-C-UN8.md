# 2026-11-12 10:02 · C · UN8 — the Notes page

**Built** (branch `claude/unit-notes-un8`, stacked on UN5's `claude/unit-notes-un5` #2284, PR #2287).
Merges after UN5. Like UN5, it needs UN2 (#2281) on the server before it shows anything but an error.

- `apps/web/src/pages/NotesPage.vue`, the wall (D-UN13): every note of the carrier, newest first, each
  row naming its unit. It uses the same `GET /api/notes` as the drawer, with no `subjects`. The
  drawer's search runs here with three filters: unit kind ("All units", Trucks, Drivers, Trailers),
  author, and days (`DateRangeFilter`, presets off). All of them live in the URL (`q`, `kind`,
  `author`, `from`, `to`), so a link carries the view. The page also has the drawer's 10 s refresh
  (D-UN10).
- A row's unit name opens that unit's drawer in place, on that note (`?notes=&note=`), through the one
  `<NotesDrawer />` the page mounts. The page has no composer: a note is always about one unit
  (D-UN1), and the drawer is where you choose it.
- Pins do not jump the queue on the wall (`NotesList`'s `pinned-first` is off). A pin is a fact about
  one unit, and lifting every unit's pin above the newest note would bury the latest news.
- **The `/notes` route in `router/routes/core.ts` now points at `NotesPage.vue`. The workaround
  comment UN0 put there is deleted** (D-UN14). The route table snapshot does not record components,
  so it did not move; `notesPageRoute.test.ts` pins that `/notes` loads `NotesPage.vue`.
  `routeTable.test.ts` and `navEquivalence.test.ts` pass unchanged.
