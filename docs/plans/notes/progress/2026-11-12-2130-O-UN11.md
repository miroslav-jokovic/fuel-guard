# UN11 — edit, remove, unit mentions on the board: contract, api, web (O, 2026-11-12 21:30 CT)

**Built.**
- Contract: `UnitNote.editedAt` / `.units`; the unit token (`unitNoteUnitToken`, `unitNoteUnitTokens`,
  `unitNoteBodyParts`, `unitNoteBodyText`); `unitNoteEditSchema`, `unitNoteResolveSchema`,
  `unitNoteUnitsQuerySchema`. Named permission `notes.manage_all` ("Edit and remove anyone's note",
  shipped to nobody but the admin). Board row `noteMentions`.
- Api: `PATCH /api/notes/:id`, `DELETE /api/notes/:id`, `POST /api/notes/:id/units/resolve`
  (`changeRoutes.ts`, its own file for the 200-line function budget), `GET /api/notes/units`; a typed
  `@848` naming exactly one truck or trailer becomes its token on add and edit (`noteUnits.ts`); an edit
  rings only the people it adds; audit rows `notes.edited`, `notes.removed`, `notes.mention_resolved`
  with `byAuthor`, never the words. `holdsNamedPermission` beside `requireNamedPermission`. The board reads
  `unit_note_open_unit_mentions` per request after its row cache, only for a `notes` screen holder.
- Web: the row's Edit / Remove menu (`NoteRow`, `NoteEditor`), "Edited"; `@` list offers trucks,
  trailers and drivers (`useNoteTypeahead` on chat's typeahead, which gains `MentionCandidate.token` /
  `.detail`); the Warnings cell's chips with Resolve (`BoardNoteChips`).

**Measured / proved.** Mutations each turned a test red: board's `readsNotes` gate, `p_any` from the
permission, edit-only ringing, the "exactly one unit" rule for typed numbers (it SURVIVED until the
truck-and-trailer-1042 case was added), the row's permission rule both ways, the token pass-through in
`fromDraft`, Remove's confirm, the drawer holding the note's own unit, the chip coming back on a failed
resolve.

**Differs from the plan.** A chip opens the row's drawer PLUS the unit the note was written on: a note
written on Marcus naming @848 is not one of truck 848's notes, and the drawer otherwise would not hold it.
