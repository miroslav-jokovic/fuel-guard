## What was built

- `features/dispatch/boardNotes.ts`:
  - `boardNoteTargets(row)` lists the units on a row: the truck; the driver and, on a team truck,
    the second seat (`driver`, `coDriver`, UN6a); and the current load's trailer (`trailerId`,
    UN6a). The order is `UNIT_NOTE_KINDS`, capped at `UNIT_NOTE_MAX_SUBJECTS`. One person in both
    seats counts once.
  - `boardNoteSummary` adds up the units' counts and takes the newest `lastAt` by the instant, not
    by the text.
  - `boardNoteUnitsWords` writes the cell's screen-reader label.
- `features/dispatch/BoardNotesCell.vue`: "count · age" or a quiet "Add", in `NotesCell`'s words
  (`noteAge`, `noteCount`) on `AppButton variant="link"`. A click opens ONE drawer through the URL:
  `?notes=vehicle:…,driver:…,driver:…,trailer:…`. `@click.stop` keeps the row's truck drawer from
  opening under it.
- `DispatchBoardTable.vue`: one `useUnitNoteSummaries(["vehicle","driver","trailer"], …)` for the
  whole board, which is the three kinds in one call (§6). It refreshes every 60 s and whenever the
  board's rows are rebuilt (`generatedAt`). The board's first load does not count as a refresh.
- `pages/AssignmentsPage.vue`: `<NotesDrawer />` beside `DispatchTruckDrawer` (ruled in
  `2026-11-12-0920-O-status.md`), plus **one more line, flagged below**.
- The drawer is UN5's, unchanged. With several units it names each note's unit with a chip, and its
  composer asks which unit a new note is about. Nothing was added for D-UN12's "chip per unit".

## Differed from the plan — for the orchestrator to accept or refuse before UN6's turn

1. **`AssignmentsPage.vue` gets more than the mount.** Its column catalogue line becomes
   `useTableColumns(BOARD_COLUMNS_ID, () => withNotesColumn(BOARD_COLUMNS, notesOn.value, "warnings"), …)`,
   plus `const notesOn = useNotesAccess()`. This is the only place the board's column list is built
   for both the table and the picker. Gating it anywhere else would leave "Notes" in the picker for a
   viewer without the surface (D-UN14), which is how C gated the Drivers catalogue. That is 3 lines
   beyond the mount, and the same kind of ask as C's `DriverRosterTable.vue` line.
2. **`pages/AssignmentsPage.test.ts` gains the notes mocks** (C's `notesOff()`/`notesStub()`), because
   it mounts the page without a query client. `notesOff()` stubs only the one-kind
   `useUnitNoteSummary`, so the mock adds `useUnitNoteSummaries` inline. **For C:** adding it to
   `notesOff()` would let the next page use it as-is.

## Found by the browser pass — for track C (their file, not routed around here)

**A failed count reads "Add", which says "no notes".** With `/api/notes/summary` answering 500 and
the board fine, every Notes cell said "Add". This is the board's, and also Vehicles', Trailers' and
Drivers', because `useUnitNoteSummaries` returns `{}` on failure and exposes no error, so no cell can
tell "none" from "could not ask". The drawer itself is honest ("Could not load the notes." with
Retry). Recommended: `useUnitNoteSummaries` also returns `failed`, and the cells draw the table's
dash with a title instead of "Add". This is a change to C's hook and cell. D's cell picks it up with
one line once it exists.
