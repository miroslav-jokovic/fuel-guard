# Unit notes — progress entries

One file per entry, so parallel chats never edit the same lines
(the lesson of `docs/plans/recruitment/ads-progress/`, 2026-11-06).

- Name: `YYYY-MM-DD-HHMM-<track>-<step>.md`, for example `2026-11-12-0930-A-UN1.md`. Time is Central.
- Tracks: `O` orchestrator, `A` database, `B` API, `C` web core, `D` dispatch, `E` mentions.
- Add the file in the step's own PR.
- Say: what was built, the PR number, what was measured, what differed from
  [`UNIT-NOTES-PLAN.md`](../UNIT-NOTES-PLAN.md), and anything another track must know.
- A change you need in a file your track does not own is an entry here, not an edit there.
- Never edit another entry. A correction is a new entry that names the one it corrects.
