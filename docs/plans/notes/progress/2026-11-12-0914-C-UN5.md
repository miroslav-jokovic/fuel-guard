## U6, answered before the columns were built

**Do the four tables share one column-definition shape, and do saved views tolerate a new
default-visible column?** Measured on `origin/main` `a82e63d`:

| Table | Where its columns live | Picker / saved views | What a new column needs |
|---|---|---|---|
| Vehicles | `const columns: DataTableColumn[]` inline in `VehiclesPage.vue`, `width` from the scale | none | the line, and the page hands `DataTable` a filtered copy |
| Trailers | the same, inline in `TrailersPage.vue`, **no** `width` on any column | none | the same |
| Drivers | its own catalogue, `features/roster/driverRosterColumns.ts`, read by `useTableColumns(ROSTER_TABLE, …)` | `ColumnPicker` + `SavedViewMenu` | the catalogue line; the page filters it by the surface |
| Dispatch Board | track D's | its own | UN6 |

All three are `DataTableColumn` (`@silvicom/ui`), so one `NOTES_COLUMN` and one placement rule
(`withNotesColumn`, after File) serve all of them. **Saved views tolerate it:** `useTableColumns`
stores a HIDDEN-list (`?hide=` and `fg.cols.<table>`), so a reader who never chose, and every saved
view that hides other columns, gets Notes; a stored key for a column the viewer does not have is
ignored. A viewer without the `notes` surface never sees the column in the table or the picker.

**The one per-table difference that mattered:** the roster's cells are not drawn by
`DriversPage.vue` but by `features/roster/DriverRosterTable.vue`, whose `DataTable` does not forward
the page's slots. See "Differed from the plan" below.

## What was built

- `apps/web/src/components/notes/` — `NotesCell.vue` (count + age, a quiet "Add"), `NotesDrawer.vue`
  (`SlideOver` `lg`: composer, search + author + `DateRangeFilter` without presets + "All units",
  pinned, list), `NoteComposer.vue` (the contract's `unitNoteCreateSchema` decides "ready"; the
  owner's `UNIT_NOTE_AUDIENCE_LINE`; a unit picker when a drawer holds several units), `NoteRow.vue`,
  `NotesList.vue` (shared with UN8's page), `NotesButton.vue` (detail pages), `notesColumn.ts`,
  `noteWords.ts`, `useUnitNotes.ts` (access, summary, the feed with D-UN10's refresh, add, pin,
  people), `useNotesDrawer.ts` (`?notes=&note=` through `parseNotesParam`/`formatNotesParam`), and
  `notesTesting.ts` (the "no notes surface" mock other pages' tests use).
- The Notes column on Vehicles, Trailers and Drivers (after File, default visible), the "Notes" button
  on the three detail pages, one `<NotesDrawer />` per page.
- Every column, button and drawer asks `useNotesAccess()` — `canReachSurface` + `surfaceAllowed` on
  the catalogue's `notes` line, the sidebar's own question (D-UN14). While the surface is dark that is
  admins only, and nothing is requested for anybody else (tested).

**D-UN10 as built:** an open drawer asks `after=<newest it holds>` every 10 s while the tab is visible
and lays the answer on top; focus refetches the list (vue-query's default), which is also how another
person's pin arrives. Close matches are not polled. The column's counts: one request per table
(never per cell — each observer of a `refetchInterval` query keeps its own timer), every 60 s, on
focus, after a note is written, and when the table's own list refreshes (`dataUpdatedAt`), skipping
the list's first load, which the counts are already being fetched alongside.

## Questions for other tracks

- **B (API) — the pinned note on a unit with more than one page of notes.** The drawer shows the pin
  from the notes it holds. A unit whose pinned note is older than its newest 50 would show no pin until
  the reader pages back to it. Recommended: when `subjects` names units and there is no `before`, the
  first page also carries each named unit's pinned note (the contract's `orderUnitNotes` already sorts
  it first, so the web needs no change). Otherwise a contract change (O).
- **B / UN3:** the author filter reads `GET /api/notes/people`. Until UN3 merges the request fails and
  the filter hides itself rather than offering nobody.
- **D (dispatch):** mount nothing new — the board's page mounts one `<NotesDrawer />`, and a row opens
  the merged drawer with `useNotesDrawer().open([{ kind, id, label }, …])` (up to 8). With several units
  the composer asks which one the note is about and every row names its unit. For the counts,
  `useUnitNoteSummaries(["vehicle","driver","trailer"])` asks for the three kinds in ONE call.
- **E (mentions, UN7):** `NoteRow.vue` draws `<@id>` as "@name" with chat's `chatBodyText`, names from
  `/api/notes/people`. The chip and `NoteComposer.vue`'s typeahead are yours once this merges.
