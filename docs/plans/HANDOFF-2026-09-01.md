## 3. Traps — the part a fresh chat would waste a day rediscovering

### 3.1 Working practice (this cost real time today, twice)

- ⚠ **`supabase db query --linked` needs the repo root, and `cd`-ing there strands you.** Twice today a
  measurement `cd`-ed to the main checkout and the *next several edits* — including a whole migration
  and its matrix — were written into the **shared working tree on another session's branch**, along
  with a full gate run that therefore proved nothing about the real branch. Nothing was committed
  wrongly and both times the work was moved and re-verified, but it cost a full re-run each time.
  **Always use a subshell: `(cd /Users/…/FuelGuard && supabase db query --linked "…")`.**
- ⚠ **The shared working tree belongs to another chat.** It sat on `claude/inspection-claim-scope` all
  day. Use `git worktree add .claude/worktrees/<topic> -b claude/<topic> origin/main`, and check
  `git branch --show-current` **and `pwd`** before every commit.
- **A fresh worktree needs** `pnpm install`, `pnpm --filter @silvicom/shared build:rn`, and both `.env`
  files copied, or ~14 suites fail for reasons that are not your change.
- **`pnpm build` needs `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`** in the environment (CI passes
  dummies). Without them the web build fails at config load, which looks like a code error and is not.
- **Prettier is NOT in CI and the repo is not prettier-formatted.** Do not run it on a file you touch —
  it produces a large unrelated diff. Match the surrounding style by hand.

### 3.2 Schema and data

- ⚠ **PGlite's session timezone is `Etc/GMT+6`, not UTC.** A bare `where fueled_at >= '2026-09-01'` in a
  matrix therefore means 06:00Z and answers a different question than the same string does in
  production. Write instant bounds as explicit `::timestamptz`. (`supabase/tests/fuel-business-date.test.mjs`
  says so at the assertion that needed it.)
- ⚠ **A full-table `UPDATE` on `fuel_transactions` fires two other triggers.** `trg_ftxn_updated`
  stamps `updated_at = now()` on **every fill in the carrier's history**, and `trg_fuel_txn_satellites`
  does up to three satellite upserts per row (~44k writes) each with its own timestamp. 0287 mutes both
  for its backfill and re-enables them in the same transaction; copy that if you write another one.
  Verified in production afterwards: `updated_at` still spans 11 distinct days back to 2026-08-06.
- **`lint:table-writers` hides the schema-snapshot check.** A migration must `git add` the regenerated
  `supabase/schema.generated.sql`, or the gate fails on an unstaged diff.
- **Hold a reader PR until its column exists in production.** `migrate.yml` applies ~12 min after merge;
  Railway serves ~3 min after. #448 was held and the column checked with
  `select … from information_schema.columns` before merging. Do the same.

### 3.3 Architecture

- ⚠ **`samsara -> anomalies` is deliberately NOT in `check-feature-boundaries.mjs`' allow-list.** The
  collector must not depend on the scoring module — that is D-ARC1 and the whole inversion the Samsara
  plan is about. A collector tier that needs scoring work **dispatches a job kind**
  (`startRebuildOnBoot`'s pattern, now also SAM-S3's). Do not add the edge.
- ⚠ **`startSamsaraScheduler` was at the 200-line function budget** and SAM-S3 pushed it over. It is now
  an orchestrator plus one function per tier. **Adding a tier means adding a function**, not a block.
- **`skipRecon` writes no terminal marker.** The branch in `resolveReconciliation` is empty, so a
  skipped fill keeps a null `samsara_recon_at`. D-SAM3's "enqueue instead of dropping" needed no queue:
  the claim predicate is the queue. Do not build a second one.
- **`anomalies` is a different table from `fuel_transactions`** and has its own `fueled_at`. That is why
  Alerts is the one fuel surface T1 does not reach (Q-FUI13).

Both answers need the tier to have run in production at least once. It is merged, so the first ticks
happen on the next scheduler deploy — **check `jobs` for `kind = 'backfill'` rows with a `batch` stat
before assuming it has run**, and re-measure `samsara_recon_at is null` to see the claim count falling.

## 8. Method, which is not negotiable

- **Measure before claiming, and re-measure the plan's own numbers before quoting them.** One plan's
  headline was 25% off. State deviations; correct the plan in place, struck through, not overwritten.
- **Prove every test can fail** by mutating its subject, and say in the PR which mutations you ran.
- One step per PR, branched from `origin/main` **explicitly**, CI green, merge commit.
- When a step ships, mark it **DONE** in its plan with "What shipped" and "Verified by:" naming real
  test titles. When a question is answered, strike it through in place with the answer and the date.
- **When the honest fix is out of scope, record it as an open question with a recommendation** — that
  is where Q-FUI12 and Q-FUI13 came from. Do not route around it.

**Confirm reality before trusting any of this:** `git log --oneline -10 origin/main`, `pnpm verify:live`,
`gh pr list`, `git worktree list`.
