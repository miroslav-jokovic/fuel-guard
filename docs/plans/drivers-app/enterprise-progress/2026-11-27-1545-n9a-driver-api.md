# 2026-11-27 — S1 / T1 N-9, first half (N-9a): the driver's load API and the shared contract

T1 "## N-9" is built in **two PRs**, because its driver half and its office half share no file and
together would be one ~1,500-line review:

- **N-9a (this entry):** the shared load contract, `driverLoadPhase.ts`, and the driver's `/api/me/loads`
  routes. Everything N-17 (the app) reads.
- **N-9b (next):** the office half — `LoadDispatchSummary.acknowledgements / reachable / seatNote`,
  the three exception kinds, "Driver's phone last reached us", and the web words.

## What N-9a changes

- `GET /api/me/loads` asks `driver_visible_tms_load_ids` (0661) which McLeod loads are the driver's; the
  TypeScript restatement of 0655's rule (`tmsLoadsVisibleTo`) is gone. An RPC error throws.
- Delivered / canceled loads are listed for 14 days on `coalesce(external_closed_at, completed_at)`
  (D-MK25), in the list only — the action door still takes late evidence.
- Loads, stops and photos are read in pages and id chunks, each org-filtered.
- A load now carries `source`, `customer_name`, and `acknowledged_at` (this driver's "Got it" on the
  CURRENT dispatch); a stop carries `external_status`, `actual_arrival_at`, `actual_departure_at`,
  `mcleod_removed_at`. All default, so an app parses an older API.
- `POST /api/me/loads/:id/acknowledge` ("Got it"). Every action passes `p_action_id`; Complete passes
  `p_arrived_at`, `p_arrive_action_id` and each photo's `sha256`. `p_mcleod_write` is not sent (T-5).
- Every 200 is `{ load, status }` with the function's own outcome (`recorded | replayed | photos_added |
  already_done | late_evidence`); late evidence is a 200 (D-MK20). DL012–DL015 have codes.
- `nextStop` / `stopProgress` read `isStopBehindTruck`: a stop McLeod departed or removed is behind the
  driver (Q-MK3). `driverLoadPhase(load)` gives `awaiting_ack | upcoming | current | previous`.
- The six load routes moved to `routes/meLoads.ts`; `me.ts` is 323 lines (was 462).
- `load_events` budget 50 → 1,500/day, `load_stop_photos` 500 → 1,400/day (audit A-40).

## Where the build differs from T1's text, and why

1. **The growth budgets live in `scripts/table-modules.json`**, not `scripts/table-lifecycle.json`
   (no such file; `check-table-lifecycle.mjs` reads table-modules.json).
2. **The 5xx body already carries a code** (`internal_error`, `middleware/errorResponder.ts:55`). T1 asks
   for `server_error`; renaming it would change a code every client already sees for nothing, so it stays.
3. **Refusals keep the API's `{ error: { code, message } }` envelope** rather than a bare `{ code,
   message }`: the driver app already reads `error.code` (`apps/driver/src/lib/api.ts:126`).
4. **"Got it" without an action id is refused by the function (DL015 → 422), not by body validation.**
   The route validates with the id optional so the requirement has one home; strict validation would
   have answered 400 `invalid_request`, not T1's 422 `action_id_required`.
5. **`driver_add_stop_photos` takes no `p_action_id`** (0661 kept 0645's signature; its replay key is
   each photo's id). The contract accepts `action_id` on that body for one outbox shape; the API does
   not pass it.
6. **D-MK25 applies to both sources.** A closed load with neither `external_closed_at` nor
   `completed_at` is not listed (a manual cancel may set neither — not measured). On production
   2026-11-27 only 1 of 195 active drivers has an app login, so at most one phone can notice.
