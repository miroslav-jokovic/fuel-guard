## 2. What to know before touching the roster or the driver page

- **Nothing writes `drivers` from the browser.** R6a found the roster's edit drawer writing through
  PostgREST, so `resolveDriverUpdate` never ran: the row was never claimed and the sync overwrote the
  correction on its next sweep, with nothing audited. 282 of 287 live drivers were exposed.
  `useDrivers.test.ts` pins the class; `useUpdateDriver` was deleted, not merely stopped being called.
- **Each driver field has exactly ONE editor.** `DRIVER_INLINE_EDITABLE` (shared) is the boundary:
  the record page edits those in place, the roster drawer keeps the fields that need a warning before
  they claim a row. `apps/api/src/driverFieldOwnership.test.ts` checks the list against McLeod's and
  Samsara's real writers AND that the two surfaces do not both offer a field.
- **A view IS a URL** (D-ROS14). Filters, sort, page and column choice are query parameters; a saved
  view is a name plus that query string. Adding a filter therefore makes it savable for free.
- **`?section=` is a public surface** and every historical value still resolves — three of them
  redirect to `/recruitment/:id` since R7. `driverSections.test.ts` passes unchanged through all of
  it, deliberately, so "unchanged" is checkable with a diff.
- **Four gates now hold decisions this programme paid for:** `lint:capabilities` (canManageFleet
  stays deleted, `requiresManage` names a section, no third driver editor),
  `routeReachability.test.ts` (no page reachable only by typing the URL), `driverFieldOwnership`,
  and `useDrivers.test.ts`.

## 3. Traps that already cost time in this programme

**`pnpm typecheck` can pass on a stale `packages/shared/dist`.** It resolves `@silvicom/shared`
through `dist/`, which is gitignored. CI runs `pnpm --filter ./packages/shared build:rn` first and
therefore sees the truth. This failed a CI run that had "passed locally". **Run `build:rn` before
trusting a local typecheck on any contract change.**

**`pnpm -s typecheck` swallows the compiler output entirely.** Use `pnpm typecheck` when diagnosing;
`-s` only for the exit code.

**A `git ls-files` fitness function cannot see your new file until you `git add` it.** This cost a
CI round trip on PR #400: `apps/api/src/testing/testServerTeardown.test.ts` enumerates suites with
`git ls-files`, so a brand-new test file that hand-rolled its server teardown was invisible to every
local `pnpm test` run and failed the moment CI checked out a commit containing it. Same family as the
stale-`dist` trap below: **stage your work before trusting a full local run.** Its sibling assertion
is a plain-text regex over the file, so the banned call must not be named in a comment either.

**`pnpm lint` does not run every CI gate.** `lint:table-writers` regenerates
`supabase/schema.generated.sql` and fails on any diff — it is the one that most often bites. The full
list is in `.github/workflows/ci.yml` (~19 steps). Before pushing, run at least: `typecheck`, `lint`,
`lint:filesize`, `lint:funcsize`, `lint:boundaries`, `lint:ui-adoption`, `lint:table-writers`,
`lint:comment-claims`, `lint:tests`, `pnpm test`.

**Running `npx vitest run apps/web/src` directly fails with `document is not defined`** — it misses
the web package's jsdom config. Use `pnpm test`, or `cd apps/web && npx vitest run <path>`.

**Replacing an expression inside a `.vue` template attribute needs single quotes.** A bulk
`session.canManage` → `session.can("roster")` produced `v-if="session.can("roster")"` and broke 19
files at once. Inside `<template>` use `session.can('roster')`; in `<script>` double quotes are fine.

**A PGlite matrix must model `auth.users`.** `drivers` and `vehicles` carry audit triggers whose
`audit_logs.actor_id` is a real FK, so a synthetic JWT `sub` with no matching row fails those writes
**indistinguishably from an RLS refusal**. `trailers` has no such trigger and was the only table
passing, which is how it surfaced. A matrix asserting only refusals would have gone green on a
revocation that never happened. Insert the `auth.users` row first — see
`supabase/tests/equipment-section-split.test.mjs`.

## 4. Decisions a fresh chat will otherwise re-litigate

**The grid reads and navigates; the record page writes (D-ROS1).** The proposal was a monday.com
grid where every cell opens an edit modal. It was refused on evidence, not taste:
`resolveDriverUpdate` (`rosterContract.ts`) makes an edit *mean* something — editing a name claims
the row away from the McLeod sync **permanently**, and setting `status: 'terminated'` stamps the
§391.51(c) retention clock. The API returns `claimedFromTelematics` and `stampedTerminationDate` so
the UI can say what an edit did; a cell editor has nowhere to put that sentence. Take monday's
**grid** (column picker, saved views — R3), not its **editor**.

**`/drivers/:id` stays and `?section=` is a public surface (D-ROS5).** `driverSections.ts:1-8` says
so; notifications (`notificationRoute.ts:18`), the binder and the applicant board all depend on it.
The complaint was six tabs, never the URL.

**Expiry columns read the qualification rollup, never `drivers.*_expires_at` as truth (D-ROS9).**
`certifications` is the single source of truth (D-DQ6) and the only table the hazmat gate reads.

**No stacked modals (D-ROS8).** Design contract §6.2 forbids it, and `DocumentPreview`'s `@media
print` rules target a single `.print-target` panel — a stack breaks the **audit print path**, which
is the product's actual job during a DOT visit.

**R5's documents modal is a `roster` surface wanting a `compliance` component.** That is a
`lint:boundaries` violation waiting to happen. It needs a sanctioned placement, not an import.

## 5. Open questions — get a ruling before the step that needs them

Q1–Q5 and Q8 are all answered; the plan's §6 carries each ruling with the measurements behind it.
**Two remain**, and both are about the product asserting more than its evidence supports:

**Q6 — may the DQ file read `current` on a date with no scan behind it?** `buildDqFile` computes
`present = Boolean(cert ?? record)`, and R1 files certifications from a TMS field — so a synced
credential reads `current` with no certificate on file, while §391.51(b)(6)(i) wants the artifact,
legible. Every synced row carries `SYNC_NOTE` (`evidence/syncedCredentials.ts`) so the fix can find
them. The honest fix is a `documented` flag distinct from `present`, touching the queue, the roster
columns and the binder. R5's file cell already counts SCANS rather than dates, which is the same
distinction stated as a fact rather than a verdict.

**Q7 — is a LAPSED requirement "due"?** `buildAttentionStrip`'s tile counts `soonest >= 0`; the
filter that tile APPLIES excludes only `soonest > days`. So it reads "Due in 30 days: 2" and opens a
list of 3. Both behaviours are preserved exactly and pinned by "disagrees with the attention tile
that sets it, for the overdue driver (recorded, not endorsed)". My reading: the filter is right and
the tile under-reports the work — but it is a number a safety manager may already be quoting.

## 6. What changed underneath you

If you read code or docs written before 2026-08-31, these are now false:

- **`DriversPage.vue` no longer owns the table, the columns, or the filters.** The table is
  `features/roster/DriverRosterTable.vue` (takes its columns as a PROP), the catalogue is
  `features/roster/driverRosterColumns.ts`, and the filters are `features/roster/useRosterFilters.ts`.
- **The roster's state lives in the URL**: `q`, `status`, `show`, `sort`, `dir`, `page`, `hide`.
  Defaults are never written, and every read is normalised — add a parameter the same way.
- **`DataTable` gained `pin-first-column`.** Do NOT hand-write `sticky left-0` on a column; three
  pages used to, and the third coordinated piece (`group` on the row) is easy to forget.
- **`createApp` no longer mounts routers directly** — they live in `mountApiRouters()` in the same
  file. They must STAY in `app.ts`'s source: `routeAuth.test.ts` and `routeGates.test.ts` both find
  routers by reading that file.
- **A new `/api` mount must carry a role gate or be pinned in `routeGates.test.ts` with an argument.**

If you read code or docs written before 2026-08-30, these are now false:

- **`canManageFleet` and `session.canManage` no longer exist.** Use `session.can(section)` /
  `session.canView(section)`. `requiresManage` route meta **names a section** and `RouteMeta` is
  typed, so a bad section name is a compile error.
- **The `fleet` section is gone**, replaced by `roster` (people) and `equipment` (trucks). A third,
  `settings`, was added for the operations console — its membership is exactly the old
  `canManageFleet` set, so no role's access changed.
- **`safety_manager` can no longer write `vehicles`/`trailers`** through PostgREST (migration
  `0277`, live in production). They keep `roster: manage` and `equipment: view`.
- **Four roster mounts stay hand-listed on purpose** — `credentials.ts` and `drivers.ts`'s invite,
  `/reconcile` and `/:id/merge`. Deriving them from `rolesThatManage("roster")` would widen the
  **irreversible** driver merge to `safety_manager`. Each carries a comment saying so. Do not "fix"
  them.
- **`insertCertification`'s `userId` is `string | null`** — a sweep has no user, and `created_by` was
  always nullable.
- **The McLeod sweep now writes `certifications`** via `evidence.recordSyncedCredentials`, under a
  **write-only-on-change** invariant. If you ever see that sweep filing rows every night, that is the
  bug: `insert_certification` supersedes unconditionally and the table is unprunable.

## 7. Working rules this programme is held to

- One step per branch (`claude/<topic>`), PR to `main`, merge after CI. **`main` is
  branch-protected.** Verify `main` actually moved after a merge; never echo success.
- **A merged migration is a deployed migration** — `migrate.yml` auto-applies to production Supabase
  on merge. Get an explicit go-ahead before merging one.
- **No workarounds** (root `CLAUDE.md`, and D-ROS11). If a step is blocked by a missing capability,
  build the capability or stop and write the blocker into the plan's §6 with candidate answers and a
  recommendation. Two of this session's best outcomes — the `fleet` split and the `settings` section
  — came from stopping and asking instead of routing around.
- **Mark each step DONE in the plan in place**, with a "What shipped" list, the deviations, and a
  "Verified by:" line naming the gates actually run. Deviations get written down, not smoothed over.
