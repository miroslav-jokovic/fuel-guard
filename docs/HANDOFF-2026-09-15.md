### What LM4 has to get right (all measured, none recalled)

- **Its own cursor row.** `samsara_feed_cursors`, `feed = 'vehicle_positions'`, distinct from the
  existing `vehicle_stats`. Sharing one would let the 5-second tier consume the deltas the 20-minute
  fuel tier needs, and **the loss would be silent** — fuel-drop detection would simply stop seeing
  intermediate samples.
- **Terminate on an empty page, never on `hasNextPage`.** Samsara's own sample code drains while
  `hasNextPage` is true, and their TMS guide warns you will "silently lag" otherwise. **On this
  organisation `hasNextPage` is ALWAYS true** — re-measured 2026-09-01, twelve pages deep, including
  on a single-sample page and an immediate re-poll of an idle fleet. Following the vendor literally
  hangs the tick forever. Copy `STATS_FEED_MAX_PAGES` + `feedPageHasData` from `samsaraStatsFeed.ts`.
  This is D-LM1d, written down because the next reader to check our code against their docs will
  otherwise "fix" it.
- **Interval `SAMSARA_POSITIONS_SYNC_SECONDS`, default 5** — the vendor's stated floor
  (*"You should not request updates more frequently 5 seconds"*), costing 0.2 req/s against a
  50 req/s per-org limit.
- **The stats feed already carries what the map needs.** `types=gps` returns `headingDegrees`,
  `speedMilesPerHour`, `isEcuSpeed` and `reverseGeo.formattedLocation`. No second integration is
  needed for marker rotation. `accuracyMeters` exists **only** on
  `/assets/location-and-speed/stream`, which is the sole reason we would ever move.
- **`RawGpsPoint` in `packages/shared/src/samsara/core.ts` does not model `headingDegrees` or
  `isEcuSpeed` yet.** LM4 adds them.
- **Bootstrap is free.** Samsara prescribes a one-time snapshot then deltas, and
  `makeSamsaraGpsSnapshotFetcher` (fleet-wide `GET /fleet/vehicles/stats?types=gps`) already exists.
- Register with `samsaraFeedHealth` so the staleness alarm covers the new tier (D-SAM6). Runs in the

## 4. Things the plans asserted that turned out to be wrong

Corrected in place, listed here so nobody re-derives them:

1. **`vehicles` has no `unique (id, org_id)`.** LM2 said it "already exists". It does not — the
   uniques are `(org_id, unit_number)` plus partial indexes on the mcleod, samsara and vin keys.
   0341 adds it, as 0148 did for `loads`.
2. **The live-map interval was 30 s and should be 5 s.** Read at source: the vendor recommends 5–30 s
   and states 5 s as a floor. D-LM1, D-LM8 and D-LM9b are all edited; the stated freshness bound went
   from ~55 s to **~15 s**.
3. **Samsara documents nothing about map smoothing or interpolation.** Searched for it specifically.
   D-LM8's animation is our design, not a copied spec.
4. **`fuel` cannot gate fuel spend** (a dispatcher holds `fuel: view` by design) and **`accounting`
   overshoots** (`fleet_manager` holds none, and the `accountant` role was granted `fuel: "view"` on
   the recorded reasoning that spend is readable under `fuel`). The matrix does not model the
   volume/cost distinction at all — hence the per-element `moneyGate.ts`.
5. **A west-positive longitude is NOT refused by `vehicle_positions`, and must not be.** My own
   migration header claimed otherwise; the matrix I wrote caught it. `+88` is a legal longitude and a
   carrier east of Greenwich would run a fleet of them.
