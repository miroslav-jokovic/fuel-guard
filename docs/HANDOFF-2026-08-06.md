## 4. How to work in THIS environment (non-obvious — read carefully)

**Filesystem / where the repo is.** Work through `mcp__remote-devices__device_bash` (runs on the user's
Mac, in a Linux VM with the repo mounted). From the shell's home, the repo is `mnt/FuelGuard` and the
source-of-truth repo is `mnt/HazmatGuard`. `cd mnt/FuelGuard` first. **Path-doubling trap:** after
`cd mnt/FuelGuard`, use paths RELATIVE to it (`apps/api/...`), never `mnt/FuelGuard/...` again. The Read
tool CANNOT see the mount — read device files with `device_bash` (`sed -n`, `cat`), edit with a
`python3` heredoc doing exact `str.replace` with `assert s.count(old)==1` guards.

**Verification ceiling = typecheck.** `node_modules` hold macOS native binaries; the VM is Linux-arm64,
so **vitest/rolldown/esbuild native bindings are missing** → `pnpm test` and `vite build` FAIL here
(not a code problem). You CAN typecheck: per package, `cd <pkg> && npx tsc -p tsconfig.json --noEmit`
(or `npx vue-tsc ...` for `packages/ui`, `apps/web`, `apps/admin`). `pnpm` is not on PATH and corepack
has no network — call `npx tsc`/`npx vue-tsc` directly per package. Always typecheck the packages you
touched before committing. Hand the actual test run to the user.

**Git is partly locked.** The mount forbids `unlink`, so stale `.git/index.lock` + `.git/HEAD.lock`
cannot be removed, which blocks `git commit`, `git branch -f`, and `git update-ref`. **Working commit
recipe** (bypasses the locks entirely):
```
cd mnt/FuelGuard
export GIT_INDEX_FILE="$PWD/.git/tmp_ci"; rm -f "$GIT_INDEX_FILE"
git read-tree HEAD
git add <files>
TREE=$(git write-tree)
COMMIT=$(printf '%s\n' "subject" "" "body..." "" "Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>" "Claude-Session: <url>" | git commit-tree "$TREE" -p HEAD)
echo "$COMMIT" > .git/refs/heads/main
```
HEAD tracks `main`; writing `.git/refs/heads/main` moves both. **Commit hazmat/dashboard work to `main`**
(user's standing instruction). Cannot `git checkout` (would delete files via unlink). The user also
commits my file changes on their side sometimes — `git log --oneline` first to see their commits and
never assume `main` is where you last left it.

**Bridge drops.** If `mcp__remote-devices__*` tools vanish mid-session, the user's Mac slept; only
`get_device_info` may remain. Wait for reconnection; don't retry in a loop.
