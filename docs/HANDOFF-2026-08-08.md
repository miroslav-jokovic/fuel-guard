## What was built this session

**The audit binder** (`docs/plans/safety-dqf/DQ-BINDER-PLAN.md`, now marked BUILT with a §6 recording
where the build left the plan). An auditor names a sample of drivers; one action produces their
§391.51 files as a single PDF, in the order named, ready to print or attach.

The five things worth carrying forward, because they are decisions rather than code:

1. **pdfkit cannot merge an existing PDF.** It draws pages; it cannot copy them in. `defensePacket.ts`
   avoids the problem only because hazmat evidence is photographs. A qualification file is largely
   PDFs and `sharp` cannot read those either. Hence pdf-lib — pdfkit still authors every drawn page.
2. **The output has its own bucket, its own clock and no client policy at all.** A finished binder is
   a PII aggregate. Seven days, then the bytes go; the ledger row does not.
3. **`dq_exports` is deliberately unreferential.** `driver_ids` is an array and `job_id` is a plain
   uuid, because a foreign key makes a historical fact mutable by somebody else's delete. The `job_id`
   version of this was caught by the RLS matrix, not by review.
4. **PDF standard fonts throw on non-WinAnsi characters.** One driver named Nikolić would have failed
   an entire binder. Text is folded; it is a compromise and it is documented as one.
5. **The footer is rotation-aware.** A scan carrying `/Rotate 90` would otherwise print the export id
   up the side of the sheet — silent, and first visible on paper in front of an auditor.

Also this session: the plan documents were audited against the tree (commit 4 of the Devin prompt).
Three claimed work outstanding that had shipped; `LOADS-PLAN`'s L5 heading contradicted its own §5.4.

## How to work in this repo

**Read before assuming.** Every serious defect this session came from checking rather than trusting:
the Samsara sync clobbering manual driver edits, the outbox dead-lettering 429s, `pdfkit` being
unable to merge, the `job_id` foreign key. None of them were visible from the plan.

**The fitness functions are not advisory.** 500-line file budget (the grandfather list may only
shrink — split, don't add), 200-line functions, feature boundaries, design tokens, migration
versions, catalogue parity. When `dqFile.ts` crossed 500 it was split into `dqCatalogue.ts`, not
grandfathered. When `AssignmentHistory.vue` reached across a feature boundary, `useTrailers` was
promoted to `composables/`, which is what the checker's own comment names as the fix.

**`docs/DESIGN-SYSTEM-CONTRACT.md` is the UI contract**, measured from the code rather than from
`DESIGN-SYSTEM.md`, which is stale in three places. Miki's standing feedback, both parts of it:
inline styling instead of the shared components is not acceptable, and *"we don't create million
unnecessary pages and overcomplicate UI/UX"* — the binder's Exports view is a tab on a page that
exists, not a new nav item.

**Voice matters.** Sentence case, no exclamation marks, failures are "Could not …" and never
"Failed to", busy states are gerund + `…`, and the house move is *state the fact, then name the next
action*. §7 of the contract has ten real strings worth copying.

**The four behavioural matrices are the real test suite.** `pnpm test:rls`. They run in PGlite as
plain node scripts. If a change touches RLS, storage policies or a lifecycle rule, it belongs there —
and note that these matrices catch what code review cannot, because the properties are *absences*.

**When a test disagrees with the code, work out which is wrong.** Two `dqFile.test.ts` expectations
were wrong this session (Aug 8 + 30 days is Sep 7, and training at exactly its third anniversary is
due today, not current) and the tests were fixed. The `job_id` foreign key went the other way.

  unlinked from here; move it.
- The device bridge drops without warning. If `device_bash` vanishes from the tool list, the desktop
  app is closed or asleep — say so and wait rather than retrying blind.

unrecoverable.
